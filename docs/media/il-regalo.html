The one rule everything hangs on

The model proposes.
The code decides.

No model — NER, LLM, or agent — ever emits a CPE string directly. Models only extract entities (vendor / product / version) as JSON. The CPE is built, validated against the official ABNF grammar, and matched against the NVD dictionary by deterministic code. A CPE that doesn't parse doesn't exist. Hallucination is structurally impossible, not just unlikely.

CPE 2.3 ABNF grammar. The only exit gate — invalid never leaves.

Against 1.77M CPEs served locally from the KGCS Neo4j graph.
→
05
Classify
M1–M3 rules, purely deterministic → CVE lookup.

Escalation, not brute force: a two-model cascade (qwen3-1.7b for the bulk, qwen3-8b for the non-M1x tail) is what the 487k-title raw run uses — and everything either model submits is re-validated by code anyway.

Where every title lands

M1 · M1A · M1B · M1C

High confidence. Exact dictionary match, accepted match, new version of a known product, or a solid brand-new CPE candidate. Ready for CVE applicability. 1.18% · 1.91% · 0.76% · 1.04% of the 2023 baseline.

M2 · M2B

Candidates. Known vendor with a similar product, or a known product under a new vendor. 53.28% · 3.52% of the 2023 baseline — worth a human (or agent) look.

M3

Everything else. Drivers, KBs, inventory noise, and the genuinely hard tail — 38.31% of the 2023 baseline, the share the v2 exists to shrink.
